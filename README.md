# PicaView

极简看图软件——参照 Google 的 Picasa 照片查看器：快、顺滑、只看图。
无图库、无相册、无人脸、无编辑、无联网。

![tech](https://img.shields.io/badge/Tauri-2-blue) ![platform](https://img.shields.io/badge/Windows-10%2F11-lightgrey) ![license](https://img.shields.io/badge/license-MIT-blue)

## 功能

### 看图

- **打开即灯箱**：透明全屏覆盖桌面，桌面压暗，图片按视口 78% 适中悬浮居中（Picasa 式）
- **秒开**：JPEG 先显示 EXIF 内嵌预览，后台解码全图后无缝替换
- **翻页瞬时响应**：邻图预解码为视口大小的低清位图（tier），翻页即现
- **超大图不爆内存**：位图长边按视口 ×2 解码（下限 2048px），放大到约 75% 以上才后台补原图，
  100MP+ 也能开；补原图时保持当前缩放与平移，百分比始终按源像素计
- **顺滑缩放**：滚轮以光标为中心缩放，双击切换 适应窗口 ↔ 实际大小；右下角对数缩放滑块双向同步
- **动图**：GIF / 动画 WebP / APNG 自动播放
- **胶片条**：底部缩略图（磁盘缓存，二次打开秒出）
- **文件夹就是入口**：Ctrl+Shift+O 选目录、Backspace 回上级、空状态列出最近打开的文件夹；
  设置里可让它启动时自动打开上次的目录
- **幻灯片**：3 秒自动播放 + 全屏灯箱
- **信息浮层 / 详情面板**：文件名、序号、尺寸、大小、拍摄时间、相机型号；
  详情面板另有 EXIF 全量（快门/光圈/ISO/GPS…）、ICC、扩展名与真实格式是否不符、**亮度直方图**

### 显示与外观

- **主题**：深色 / 浅色 / 跟随系统（同时切换窗口标题栏）
- **只看图片**：隐藏标题栏，纯画面（入口在 设置 或 B 键；不是工具栏按钮）
- **取色（C）**：鼠标位置的源像素坐标 + 颜色，直接从源位图采样，不影响缩放流畅度
- **蒙板（M）**：图片外压暗（窗口模式下）

### 文件

- **旋转默认不改文件**：只旋转显示方向（记录在设置里，下次打开仍然有效，
  导出 / 复制 / 壁纸也按这个方向输出）。想做真正的写回，在 设置 → 旋转
  切到"直接写入文件"：JPEG 走 libjpeg-turbo 无损变换（不重编码）并复位 EXIF 方向，
  PNG 写回时保留 ICC；有损 WebP 会变无损（体积可能变大，界面会提示）
- **F2 重命名**（只允许图片扩展名，校验 Windows 保留名）
- **Delete 移入回收站 / Shift+Delete 彻底删除**（均带确认）
- **Ctrl+Z 撤销上一次旋转**（两种旋转模式都支持，最多 10 步）
- **排序**：名称 ↑↓ / 修改时间 / 文件大小；切换后保持当前图片不重新解码

### 输出与分享

- **Ctrl+C 复制图片**：长边 >4096 自动等比缩小，粘贴进聊天软件 / 文档即用
- **Ctrl+Shift+C 复制文件**：粘贴到资源管理器是文件本身，零转码
- **Ctrl+E 另存为 / 导出**：保持原格式 / JPEG / PNG / WebP，可限长边、可调 JPEG 质量；
  扩展名按实际写入的格式纠正，永不覆盖原图，已存在先确认
- **设为桌面壁纸**：统一转码为 JPEG 后调系统接口（WebP / GIF 也能用）
- 以上都可从 **⋯ 菜单**或**右键菜单**进入；右键还能"在资源管理器中显示 / 复制完整路径"
- **⋯ 菜单**里另有 打开图片 / 打开文件夹 / 快捷键（?）/ 设置…

### 记住的状态

灯箱 / 只看图片 / 胶片条 / 信息浮层 / 排序方式 / 主题 / 旋转方式，
以及"仅显示"模式的旋转角度，全部存在 `settings.json`（见 [文件位置](#文件位置)）。

## 设置项

设置面板在 **⋯ → 设置…**，改动即时生效（"打开即灯箱"下次打开图片时生效）。

| 设置 | 默认 | 说明 |
|---|---|---|
| 打开即灯箱 | 开 | 关掉后用普通窗口看图 |
| 只看图片 | 关 | 隐藏标题栏；开启后每次启动都保持（右键拖动移动窗口，Esc 退出） |
| 胶片条 | 开 | 等同 `T` |
| 信息浮层 | 开 | 等同 `I` |
| 排序方式 | 名称 ↑ | 名称 ↑↓ / 修改时间 / 文件大小 |
| 滚轮 | 缩放 | 缩放 / 翻页（翻页模式下 Ctrl+滚轮仍是缩放） |
| 恢复上次文件夹 | 关 | 启动时自动打开最近浏览过的目录 |
| 主题 | 深色 | 深色 / 浅色 / 跟随系统 |
| 旋转 | 仅旋转显示 | 换成"直接写入文件"后，之前攒下的显示角度会在下一次旋转时一起落地 |

## 设计取舍（不做）

- **默认不改写图片**：旋转、排序、显示都不碰原文件；唯一会写盘的是"旋转写入文件"（默认关闭）、
  重命名与删除（都会先确认）
- **不监听目录变化**：看图就是"打开一个目录看到底"，外部改动后重开一次即可，省掉文件监听的复杂与耗电
- **不做图库/相册/人脸/评分**：没有数据库、没有索引、没有后台进程；
  "仅显示"的旋转角度只是 `settings.json` 里的一条小记录，不是图库
- **不做编辑**：只保留无损旋转与"另存为导出"
- **不做剪切**：文件移动交给资源管理器
- **不做向导/首启教程**：空状态的两个按钮 + 最近文件夹 + 快捷键面板（?）就是全部引导

## 支持格式

JPEG · PNG · BMP · GIF（含动图）· WebP（含动图）· APNG

> 按文件**内容**识别格式：扩展名不可信（如 .png 实为 JPEG）也能正常打开、旋转与生成缩略图。

## 文件位置

| 路径 | 内容 |
|---|---|
| `%APPDATA%\com.picaview.app\settings.json` | 设置与"仅显示"旋转记录（删掉即恢复默认） |
| `%LOCALAPPDATA%\com.picaview.app\thumbs\` | 缩略图磁盘缓存（超过 30 天或 500MB 自动清理） |
| `%LOCALAPPDATA%\com.picaview.app\wallpaper\` | 设为壁纸时转出的 JPEG |
| `%LOCALAPPDATA%\com.picaview.app\picaview.log` | 诊断日志（发布版只记失败路径，超 512KB 重置） |

## 开发

```bash
npm install
npm run tauri dev                    # 开发运行
npm run gen:testdata                 # 生成测试图片到 testdata/
npm run gen:icon && npx tauri icon tools/app-icon.png   # 重新生成图标
npm run tauri build                  # 产出 NSIS 安装包 → src-tauri/target/release/bundle/nsis/
cd src-tauri && cargo test           # Rust 单测
```

环境要求：Node 18+（建议 20+）、Rust (stable-msvc)、Visual Studio C++ 工具（CMake 用 VS 自带的即可）。
turbojpeg 已禁用 `require-simd` 特性，无需 NASM。

> ⚠️ 构建发布版必须用 `npm run tauri build`。裸 `cargo build --release`
> 缺 `custom-protocol` 特性，产物启动时会去加载 dev 地址（localhost:1420），
> 没有开发服务器在跑就是空白窗口。
>
> 打包前请先关掉正在运行的 PicaView，否则 Windows 会拒绝覆盖 `picaview.exe`（os error 5）。

## 技术要点

**架构**

- Tauri 2 + 系统 WebView2，前端无框架、无运行时依赖（`src/` 共 21 个 TS 模块，颜色全部走 CSS 变量）
- 灯箱：窗口 `transparent + fullscreen + visible:false`（隐藏创建、就绪后显示），
  页面背景切换透明，桌面透出被 55% 黑色蒙板压暗，图片悬浮居中；所有偏好在首帧之前套用，
  避免"先黑后白""先带标题栏再消失"的闪烁
- 大图解码与缩略图生成都在 Rust 侧，前端只负责显示，并用 token/version 让过期的异步结果自动作废

**解码与内存**

- 图片字节经 Rust `read_image` 命令读取（支持 `\\?\` 长路径），前端转 Blob 解码；
  位图解码失败时降级到 `<img>` 通道（可显示任意尺寸），仍失败则显示错误浮层与原因
- 格式按文件内容嗅探（魔数），扩展名不可信
- 缩略图：JPEG 用 turbojpeg 在 DCT 域直接缩到接近 240px（不做"整图解码再缩"），
  其它格式退回 image crate；缓存键 = hash(路径 + mtime + 大小)
- 目录扫描按 CPU 并行做动图探测，结果按 (路径 + mtime + 大小) 缓存，重复打开同一目录无需再读文件头
- 内存策略：只保留当前全图 + 相邻图 tier 位图；胶片条每个条目只建轻量占位元素，
  缩略图画布进入视口时才挂上、移出即摘掉

**交互**

- 缩放/平移在设备像素空间计算，百分比与"实际大小"一律按源像素口径（LOD 降采样也不失真）
- 取色用 1×1 离屏 canvas 从源位图采样，绝不 `getImageData` 主画布（避免 GPU→CPU 同步拖慢缩放）
- 直方图用磁盘上的缩略图统计（一次读盘、约四万像素），不额外解码
- 排序在 Rust 侧完成，并列时一律按名称自然序兜底，顺序稳定可复现

**写盘**

- 旋转/导出/壁纸共用一套解码入口；写文件一律"同目录临时文件 + rename 覆盖（带重试）"，
  中途失败不会留下半个文件，也不会出现"旧文件已删、新文件没到位"
- JPEG 无损旋转后就地修补 EXIF Orientation 字节（复位为 1），不重写整个 EXIF；
  一次调用可转 1~3 档，方向在 D4 群里合成为**一次**变换（只读一次、写一次文件）
- "仅显示"的旋转角度存 `settings.json`（路径 + 大小 + mtime 校验，文件一变自动失效），
  上限 1024 条；切到"写入文件"时一次性落地
- 剪贴板：整图走 `CF_DIB` 位图，文件走 `CF_HDROP` 列表（arboard，Windows 后端）
- 壁纸统一转 JPEG（q92，长边 ≤8192）后调 `SystemParametersInfoW`

**工程**

- 设置写入防抖 400ms + 原子替换；解析宽松（字段缺失用默认值，整体损坏退回默认），
  绝不让配置把软件卡住
- Rust 侧 90+ 项单测（路径规范化、动图探测、EXIF 方向群运算、排序、缩略图、导出、设置）；
  CI 在 Windows 上跑 `cargo test` + `cargo clippy` + 前端构建，tag 触发打包发布
